1、BeanFactory和FactoryBean的区别
功能不同
BeanFactory是Spring框架的核心接口，用于管理和获取Bean对象。它是一个容器，负责创建、配置和管理应用程序中的Bean

5、了解https证书吗
HTTPS 证书是一种数字证书，用于证明网站或服务的身份。证书包含了网站或应用的相关信息，如名称、地址、所有者等，并使用它的私钥进行数字签名，以确保证书的真实性和完整性。
HTTPS 证书通常分为三种类型：DV（域名认证）、OV（组织认证）和 EV（增强型认证）
DV 证书通常由 CA 颁发，用于证明域名的所有权，是最基本的 HTTPS 证书。OV 证书和 EV 证书不仅会验证域名所有权，还会验证申请人的身份和组织机构信息。
相较于 DV 证书，OV 证书和 EV 证书的验证过程更严格，安全性更高，但价格也更贵。

8、聊一下mysql的MVCC
https://blog.csdn.net/wangshuai6707/article/details/132711781
MVCC 的核心思想是在读取操作时不锁住整个表或行，而是让不同的事务访问数据库的不同版本。每个事务看到的当前版本是基于其自己的事务开始时间的，
可以看作是一个时间戳，即每个数据行都有一个时间戳标识其版本。当多个事务读取同一行数据时，每个事务可以看到自己开始时间之前的所有修改。
如果两个事务同时修改同一行数据，MySQL会为每个事务创建一个快照（Snapshot）以进行编辑，相当于把每个事务看作是对某个时间点上的数据副本进行操作

        for (int left = 0, right = nums.length - 1; left < right; ) {
            //2.1.相等的话,直接输出即可
            if (nums[left] + nums[right] == target) {

1.线程池的生命周期
线程池的状态可以通过其内部维护的运行状态（runState）和线程数量（workerCount）的变量来表示。这个变量是一个32位的整型，其中高三位表示线程池的状态，后29位表示线程的数量

RUNNING:线程池可以接受新任务，并且正在执行任务，这是线程池初始状态
SHUTDOWN:线程池不再接受新任务，但仍会执行队列中的任务，线程池会等待已经提交的任务执行完毕
STOP:线程池全面拒绝任务，并中断正在处理的任务，执行shutDownNow方法会进入此状态
TIDYING:所有任务已经终止，线程池正在进行清理工作
TERMINATED:线程池已经完全终止，所有任务已终止，且清理工作已完成。此状态下，线程池生命周期彻底结束

2.MQ如何处理消息堆积
增加消费者：可以通过增加消费者的数量来提高消息的消费速度，减少消息堆积的情况
调整消费者的处理能力：可以优化消费者的处理逻辑，提高消费效率，减少处理时间，从而减少消息堆积的情况
增加消息队列的容量：增加消息队列的容量可以存储更多的消息，缓解消息堆积的压力。可以通过增加队列的分区数、增加队列的长度等方式来扩展消息队列的容量
设置消息过期时间：对于一些长时间未被消费的消息，可以设置消息的过期时间，使其在一定时间后自动过期并被丢弃，从而避免消息长时间堆积。
监控和报警机制：建立监控和报警机制，实时监控消息队列的状态和消息堆积情况，及时发现并解决消息堆积问题，防止问题进一步恶化。
消息重试和死信队列：对于消费失败的消息，可以进行消息重试，尝试多次消费。如果多次重试仍然失败，可以将消息发送到死信队列进行处理，防止消息一直堆积在主队列中
限流和流量控制：在消息生产端进行限流和流量控制，控制消息的生产速率，避免过多的消息发送到消息队列中导致堆积。

2.行式数据库和列式数据库的区别(Mysql和Hbase)
数据存储方式不同：行式数据库将数据按照行存储，即每一行包含多个字段，这种方式便于读取整个记录。列式数据库则将数据按照列存储，每一列单独存放，这种方式便于数据聚合和分析
数据检索方式不同：行式数据库在查询时，如果需要访问多列数据，会消耗更多的IO资源。而列式数据库在查询时，可以只访问查询涉及的列，从而显著降低系统IO
数据处理能力不同：行式数据库擅长随机读操作，但不适合大数据处理。列式数据库则面向大数据环境，特别是在数据分析和数据挖掘领域，列式数据库可以提供更高的压缩率和查询性能
适用场景不同：行式数据库适用于联机事务处理和需要频繁更新的交易场景。列式数据库则适用于数据仓库、数据分析、海量存储等场景，特别是涉及不经常更新的数据库

2.jdk代理和cglib代理有什么区别？谁的性能更好?
代理对象不同：JDK只能代理实现了接口的类，CGLIB通过继承目标类生成子类的方式实现
实现机制不同：JDK通过反射实现，使用Proxy和InvocationHandler类实现；CGLIB通过字节码增强实现，使用Enhancer和MethodInterceptor类实现
通常来说CGLIB的性能更好，因为它通过直接操作字节码生成新的类，避免了使用反射的开销

4.MVCC可以解决幻读吗
可以在一定程度上避免幻读现象，但并不能完全解决幻读问题
在“快照读"的情况下是可以解决“幻读”的问题的，但MVCC解决不了“当前读”导致的幻读问题
快照读的幻读是用MVCC解决的，当前读的幻读是用行锁+间隙锁解决的
